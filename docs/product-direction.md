# Parallax 当前产品方向

更新于2026-10-25，依据用户最新确认。此前以自动化买卖为核心的迁移记录保留其历史语境；当前目标以本文为准。

## 核心任务

帮助用户在明确的商品范围、预算和风险假设下判断哪些饰品值得进一步人工核查、哪些不满足规则、哪些数据不足。实际购买由用户在平台执行，持有与出售时机由用户决定。自动买卖不作为首版完成条件，BUFF直连暂缓，不开展真实订单/支付接口接线。

系统链路：限定范围 → 获取参考行情 → 显式引用Steam历史与持仓证据 → 筛选解释 → 预算方案 → 人工复核 → 可选人工购入记录与持仓复盘。

## 复用现有模块

- Scanner/Candidate：记录来源、范围、停止原因与逐项筛选结果。SteamDT中BUFF平台参考价来自SteamDT，不表示本机访问BUFF或取得实时可成交卖单。
- PlanPreview：保留预算、数量、仓位上限、原币/汇率及引用快照。分配数量是研究假设，未经真实卖单核验不能声称可买到。
- StrategyResearch：继续复用已保存版本及pass/fail/unknown，不建立新评分引擎。pass仅表示所选证据满足所配置规则，unknown不能显示为通过；未启用的风险规则不属于已检查范围。
- Steam历史与库存：保留UAH原币、默认CNY展示和汇率证据。库存来源历史用于商品研究，不自动冒充扫描采购证据、当前持仓或成本。
- Ledger/Holdings：人工购入/费用/数量记录与平台验证状态分开，允许长期持有；缺少可靠成本时浮盈亏保持未知。

## 首版验收重点（当前目标，未全部完成）

| 能力 | 要回答的问题 |
| --- | --- |
| 范围与来源 | 看了哪些商品、漏了哪些范围、价格来自哪里及何时取得？ |
| 筛选方案 | 为什么保留或淘汰，采用哪个规则版本，哪些项目无法判断？ |
| 买入预算 | 按参考价格能分配多少，是否超过单品/总仓位假设？ |
| 风险与持仓 | 历史覆盖、流动性、波动与持仓集中度有哪些已知与缺口？ |
| 人工复核清单 | 实际商品/版本、当前单价、数量、手续费、交易限制还需确认什么？ |
| 复盘 | 人工买入后的真实成本和研究时的假设如何区分？ |

优先完成从扫描到策略研究的可用闭环与证据解释，再打磨人工参考价格/成本输入和持仓反馈。清单与展示尚需逐项实现/验证，不将已有模块直接等同于整个目标完成。

## 暂缓范围与进度口径

自动锁单、下单、付款、收货确认、挂牌、手机确认、撤单及调度均不计入当前首版必需项；已有底座保留，不删除或伪装为已完成。live_execution=false保持。

旧总体25%–30%是对原自动交易全量范围的覆盖估算，不再用它直接表示当前决策辅助产品的完成度。新目标需按上述实际用户流程重新验收后再估算，不因缩小范围直接宣布接近完成。

本文为产品方向及验收合同更新，本轮不修改业务算法、不请求平台、不新增API或依赖。已有完整186项测试证据沿用前轮；仅执行文档差异和链接检查。
