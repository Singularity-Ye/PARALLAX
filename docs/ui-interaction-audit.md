# UI交互缺漏与动效交接

2026-10-26，依据当前theme.css/components.css/shell.js及页面脚本静态审查；不是全页面视觉验收。反重力恢复后优先处理下列交互，暂未实施全站动效。

当前主要为静态卡片、文本状态、即时显隐。已有hover/focus、移动导航、切页保留和结果展开，但没有成体系的请求中→成功/失败状态过渡；动画不是业务完成度。

| 场景 | 建议交互 | 必须保留 |
| --- | --- | --- |
| 导航/页面切换 | 150–220ms透明度/轻位移，活跃标记过渡 | 不重建表单、不丢输入与滚动位置，不用动画延迟可操作时间 |
| 请求进行 | 局部spinner/文字状态，按钮进入明确busy态，未知时长不造百分比 | 错误局部反馈、可继续，已有结果保留，不整页锁死 |
| 保存成功 | 原位状态过渡，可短暂强调新增记录 | 列表刷新失败不抹去保存成功，重要提示不能只靠会消失toast |
| 证据/折叠区域 | 温和展开，摘要中保留状态/来源/日期 | 原生details键盘语义，不把未知染绿 |
| 表格与比较 | 选中/hover高亮、明确排序和滚动提示 | 不为视觉隐藏失败样本，不暗改原顺序或业务排序 |
| 空状态/失败 | 显式下一步与重试反馈，保留输入 | 不以骨架屏永久替代错误，不伪造数据 |
| 令牌与代理 | 倒计时进度、测试中/响应状态 | OTP过期/离页清除，连通性不冒充认证成功 |

装饰动效避开持续闪动、每次刷新数字重跳、大面积纸纹运动和layout抖动；优先transform/opacity。prefers-reduced-motion需同时关闭animation和transition（当前主题只写transition与scroll行为），隐藏页面停止不必要动画。键盘焦点、对比度、aria-live与长表格可读性优先于观感。

先统一theme的motion时长/缓动与components状态类，再挑导航、保存反馈、证据展开三个实际场景验收；不要每页复制一套动画库或引入重型框架。确认桌面与窄屏、慢请求/失败/空列表/reduced-motion后再铺开。
