# Parallax BUFF 现金端只读报价

状态：协议适配、账户门控、快照与预算引用已实现，本地夹具通过；**真实 BUFF 登录态、线上卖单与 CNY 单位尚未实测**。不是锁单、付款、库存同步或可成交承诺。

## 复用与使用

沿用原项目 `buff/buyer.py:get_sell_orders` 的固定 HTTPS GET 形状，复用现有 reqwest、整数金额、SQLite、Accounts、CredentialStore 与会话验证。没有新增依赖、复制旧凭据或创建第二套认证状态。与原版不同：只读首屏、明确失败/空盘、TLS 验证开启、禁重定向/自动重试；报价明确绑定账户、凭据代次和扫描候选。

`./dev.ps1 run` 后：创建账户并在账户区导入/浏览器登录 → 在线核验 BUFF 身份 → 等待已有冷却结束 → 完成真实 SteamDT 扫描 → 在 BUFF 研究区选账户和候选 → 读取报价。五分钟身份有效窗口是本应用的读取门槛，不是平台会话真实有效期。

| 接口 | 行为 |
| --- | --- |
| POST /api/accounts/{account}/buff-quotes | `{scan_id,item_key}`，201 快照；只读平台 GET |
| GET /api/accounts/{account}/buff-quotes | 此账户最近十份快照 |
| GET /api/accounts/{account}/buff-quotes/{id} | 历史详情，跨账户返回 404 |

请求体最多 2 KiB，同源检查与 no-store 响应。输入无效 400/422，不存在 404，登录/挑战/代次冲突 409，限流 429 与绝对 retry_at，网络/协议问题 502。历史查询不使用凭据、不请求平台、不重新确认有效性。

## 认证与访问规则

- 仅从已完成的真实 SteamDT 扫描解析 key → goods_id；前端不能自填任意 goods_id；演示、缺映射和缺账户均在读取凭据前拒绝。
- BUFF 会话需 status=valid、subject 非空、checked_at 不在未来且距今不超过 300 秒。手工导入后 unverified 不可读单，必须先在线核验。
- 使用 Accounts 同一串行门覆盖凭据读取和整次平台 GET。导入、验证、浏览器完成、停用等待本次读单结束，防止中途换凭据。
- 复用 SQLite 中的 BUFF 全局冷却和挑战阻断。请求前写入两秒节流；身份验证已有的 30 秒冷却仍保留。429 或应用限流冷却至少 300 秒、最多七天；不自动重试或绕过限制。
- HTTP 403/412、挑战码/页面触发持久化挑战；明确未登录更新 invalid。网络失败不判登录失效，不刷新上次身份核验时间，也不保存伪报价。
- 如果响应改变 session/csrf_token，当前实现不静默丢弃或导出新 Cookie：报价拒绝，会话改为 unverified 并更新代次，要求浏览器重新获取/核验；空 session 视为失效。自动持久化 Cookie 轮换尚未实现。
- 正常 TLS、固定 buff.163.com 地址、不跟随重定向、只用 GET。错误为静态脱敏信息，不返回 Cookie、UA、用户资料、原始响应或卖家订单详情。响应体上限 2 MiB。

当前锁为单进程，SQLite 与 Windows 凭据库仍非单一事务。计划保存与会话检查也不是跨进程原子执行授权；计划永远不能直接下单。全应用部署、多进程与未决支付时冻结凭据仍待后续实现。

## 商品、金额与数量

请求固定 game=csgo、page_num=1、page_size=80、sort_by=default、allow_tradable_cooldown=0。**这些协议参数尚待真实平台验收。** 响应必须提供对应 goods_infos[goods_id].market_hash_name，与候选 key 完全相同；items 缺失为格式错误，显式 [] 才是空卖盘，空盘也必须有商品身份。

价格只接十进制字符串（最多两位小数）或整数元，整数转换为分，不用浮点；小数 JSON number 明确拒绝。重复卖单 ID 去重，同 ID 不同价格拒绝；多件 amount、错商品、异常数量/币种拒绝。原始卖家/资产等资料不持久化，快照仅存汇总档位。

CNY 单位来自原 BUFF 卖单协议假设，快照标记 currency_basis=`buff_cny_protocol_not_live_verified`；有显式 currency 时仅接受 CNY。没有响应币种证明时，不声称完成真实人民币结算验证。金额为预览研究，仍需平台样本核验。

只返回首屏可见价，不能宣称全市场最低。预算只采用首屏最低档的价格，并把该档唯一可见卖单数作为额外数量上限；较贵档位不冒充最低价库存。可见数不是已锁可买量、持仓、日量或付款保证。

## 预算合同与兼容

PlanRequest 可选 `buff_snapshot_ids`（最多 20 个唯一 ID）与 `buff_account_id`；有引用时账户必填，且必须与手工仓位所属账户一致。PlanPreview 可选 `buff_valuations` 保存账户、代次、商品、goods_id、时刻、单价和最低档可见数。旧 JSON 默认无引用，历史数值不重算。

应用层核对当前账户最近核验有效、挑战已解除、快照代次未变化；纯规划核对扫描 ID、商品 key/goods_id、币种、快照年龄及唯一性。失败不保存计划；空盘明确跳过，不退回榜单价格。其他未引用的候选可继续使用榜单估值，页面保留混合来源说明。

每侧独立更新时间：只换 BUFF 现金端时，Steam 侧仍受原榜单时效限制；只换 Steam 时同理。只有两侧都被显式有效快照替换时，才允许摆脱原报价时间。费用模型、流动性、手工持仓与最小资金限制继续复用；可分配数量取这些限制与最低价可见卖单数的更小值。旧扫描与旧计划不被改写。
