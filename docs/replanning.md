# 从保存研究重新规划预算

2026-10-25。当前实现选品到重新分配的本地用例；不是自动买入，人工采购复核到台账的完整向导仍待。

## 操作

策略中心打开已保存的预算研究，在结果底部明确勾选逐商品pass项，调整人民币预算、每商品硬上限和商品种类上限，保存新计划。fail/unknown项禁选，没有pass项则不能重新规划。试算未保存时不显示此入口。独立持有研究不含预算，暂不走此入口。

沿用原计划的扫描、报价引用、目标钱包、手工仓位及其它约束，不自动刷新平台数据。相同扫描仍需通过当前报价/仓位时效、币种/FX和凭据检查；过期会拒绝或保留逐商品跳过原因，不把旧数据变新。需要刷新扫描时须重新研究；当前不跨扫描匹配旧结论。保存成功后可在预算页查看结果/跳过原因，再到策略中心刷新记录选择新预算重新研究。

## 架构与接口

- domain/replanning只校验来源/选择并生成ResearchOrigin，不计算分配；保存研究的逐项pass是选择入口，不授权新数量。
- domain/planning的PlanRequest新增可选selected_item_keys，None沿用原全部扫描候选，Some要求1–100唯一且属于扫描。未选择商品保留明确跳过原因，原coverage不裁剪。
- application/planning从总入口提取原预算创建逻辑；create_plan与replan共用prepare_plan，包含所有原账户/报价/费用/FX检查。
- application/replanning读取不可变研究、校验来源、调用prepare_plan，追加来源后只保存一次新计划。原研究/计划不更新。
- web/lib/replanning.js负责选择和输入，调用统一API；预算页仍复用renderPlan，不复制预算表格或业务公式。

POST `/api/plans/replan`：`{"evaluation_id":"保存研究ID","request":{...PlanRequest,"selected_item_keys":["准确商品标识"]}}`，201返回新PlanPreview。同源、2MiB上限，结构/未知字段422，来源不存在404，范围/选择/账户冲突400，原报价检查错误继续沿用原语义。

新计划research_origin保存evaluation_id、parent_plan_id、account_id、research_at、完整策略版本与所选原判断，new_plan_research_required=true。原快照缺此字段继续可读，不改历史数据。旧通过结果不能当新计划通过；新数量可能改变仓位/退出等规则，需要新研究。没有预留额度、创建订单或继承预检资格。

只有原研究逐项pass可自动纳入；原整体可fail，只要明确选择的各项pass。未研究/重复/未知/失败项拒绝；新仓位或BUFF账户必须与来源研究账户一致。当前没有改规则后自动补选、跨扫描/独立研究重规划、人工覆盖失败项或请求幂等去重；网络结果不明先查预算历史，不自动重发。新计划仍可为空，此时应看跳过原因，不能描述为采购成功。
