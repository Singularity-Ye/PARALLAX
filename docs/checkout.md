# Parallax 资金观察与本地采购意图

2026-10-25：已实现并本地验证。只有本地准备与额度预留，没有平台锁单、付款或执行许可。`POST /api/trades` 仍返回 501。

## 来源与范围

提取原项目 checkout guard 的主体互斥、持久化防重及未知结果先核对思路；复用现有账户上下文、保存证据预检和 SQLite 事务，没有另建认证或策略系统。

资金按当前有效 BUFF 会话的 `subject`（BUFF 用户 ID）归属，不能按 Steam 账户编号分开计算同一份现金。新观察/准备要求 BUFF 身份核验距今不超过 300 秒且未冷却；准备还重查 Steam 会话、凭据代次和原始研究证据。身份来自本地已保存的核验元数据，本轮没有额外访问平台或凭据后端。

人工登记的是 BUFF 侧 CNY 现金参考，固定 `provenance=manual_unverified`、`platform_verified=false`；不是已验证余额。Steam 钱包（包括 UAH）独立保留，不能换标签或隐式抵扣现金。没有观察为未知，明确观察为零才显示零。

## 三个事务边界

1. **观察**：请求键精确重试返回原快照；不同输入复用键冲突。凭据编号在 BUFF 主体内唯一，新观察时间必须晚于最新快照。低余额可以保存，已有预留继续保留并显示缺口。
2. **准备**：同一 IMMEDIATE 事务内读取当前身份、校验主体互斥、引用最新资金快照、加载账户预检、用当时原始证据重新检查、保存意图及占用金额。演示/未知/过期证据不占额度；不会刷新行情时间。数据库部分唯一索引保证同一 BUFF 主体同时只有一个 reserved 意图，跨账户/连接也不能重复使用余额。
3. **取消**：仅允许本地 reserved → cancelled，校验 expected_revision，追加不可覆盖事件并更新投影。请求键精确重试不会重复释放。会话失效仍可恢复和取消自己尚未提交的平台外意图。

同一账户的一个预检只能绑定一个意图，取消后也不能用新键重复消费。精确准备重试优先返回当前记录，哪怕凭据已过期或记录已取消；不再占一次额度。资金缺口、会话到期及进程重启都不会自动释放预留。

## 模型与恢复

`PurchaseIntent` 保存账户、BUFF 主体、revision、reserved/cancelled 状态、资金原快照、重新检查的预检证据与原始请求；`mode=local_preparation_only`、`execution_allowed=false`。取消后金额仍留作历史字段，当前占用只统计 reserved 状态。

重启可列出并读取原意图；列表至多最近 100 条，同一主体只允许一个活动记录。创建事实留在意图快照，取消事件单独追加。它尚不是完整事件溯源订单系统。没有 submitted/paid 状态或虚构外部订单号，也没有“已发送但响应未知”的真实订单恢复。后续发送器必须先建立持久化尝试记录、未知结果状态与平台对账，再谈自动重试/释放。

## HTTP 与 UI

账户前缀 `/api/accounts/{account}`：

| 方法 | 路径 | 合同 |
| --- | --- | --- |
| GET / POST | `/cash-funding` | 当前资金与占用视图 / 保存人工观察 |
| GET / POST | `/purchase-intents` | 最近 100 个摘要 / 原子准备 |
| GET | `/purchase-intents/{id}` | 当前版本及原始证据 |
| POST | `/purchase-intents/{id}/cancel` | 版本化取消，仅限本地未提交 |
| GET | `/purchase-intents/{id}/events` | 取消审计事件 |

观察请求：`client_key`、`available_cash_cents`（CNY 分，0..10^12）、`observed_at`（Unix 秒）、`evidence_ref`。准备请求：`client_key`、`preflight_id`、`funding_snapshot_id`、`max_funding_age_secs`（1..300）。取消请求：`client_key`、`expected_revision`、`reason`。

POST 返回 200 `{item,replayed}`。语义错误 400、缺失/跨账户 404、键/版本/快照/互斥冲突 409、结构或未知字段 422、跨站 403；16 KiB、no-store。GET 资金视图返回对象，摘要/事件返回 `{items}`。

“操作记录 → 资金与采购准备”复用纸感主题、卡片、forms、原币金额组件和统一 api.js/api.d.ts。浏览器不计算余额或策略；失败保留输入，保存成功与后续刷新失败分别说明。恢复按钮不重新预留或访问平台。
