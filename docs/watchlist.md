# 关注列表与观察记录

状态：已实现本地持久化和手动观察；没有后台采集、收益回测或样本外有效性结论。

## 使用

策略中心沿用“研究账户”。可直接输入 CS2 准确市场名称与关注原因，或从库存、价格历史点击“加入关注列表”，从独立研究点击“关注此商品”。带入不自动保存，必须填写原因。

打开该账户已有独立研究，在关注商品旁点击“追加当前打开的研究”。研究必须包含该商品；满足、未满足、未知都可保存。查看观察记录按登记顺序展示策略版本、规则依据、未启用项、研究时间、历史采集时间和原币（含 UAH）。

“选择并读取新历史”只带入账户与名称，仍须在历史页明确点击读取；认证与冷却沿用已有 Steam 用例。读取后保存新的独立研究，再追加观察。不访问 BUFF，不后台轮询。

## 分层与复用

- domain/watchlist：关注请求、账户商品身份、观察快照；当前 app_id 固定730，名称精确匹配，不把同名商品当具体磨损资产。
- application/watchlist：账户与研究所有权、商品包含关系检查，无凭据或平台客户端依赖。
- adapters/sqlite/watchlist：新增兼容表 watch_items / watch_observations；不改写旧历史/策略数据。
- transport/watchlist：同源与4KiB请求限制、no-store响应；共用 web/lib/api.js 与类型声明。
- 观察内嵌原 HoldingResearchReport，保留完整版本和历史；规则计算/解释沿用原模块，观察保存不重新采集或重算。

同账户同市场名称重复添加返回原关注，保留首次原因；同关注同 research_id 重试返回原观察。当前未提供修改原因、归档或删除。列表返回该账户全部关注/观察，当前规模较小；分页和快照体积优化待数据增长后补充。

## 接口

`GET/POST /api/accounts/{account}/watchlist`

```json
{"item_key":"Prisma 2 Case","reason":"保留未通过样本，以后对照"}
```

`GET/POST /api/accounts/{account}/watchlist/{id}/observations`

```json
{"research_id":"已保存独立研究的ID"}
```

两个POST均200返回已保存项（也可能是去重后的原项）。GET返回 items。跨账户引用/不存在返回404，商品不匹配返回400；未知JSON字段沿用公共解析器返回422。

## 证据边界

recorded_at是登记时间，research.created_at是原研究时间，history.observed_at是采集时间。把旧研究补录进观察，不会使其成为当时已登记的前瞻样本。旧规则结果不会按今天时间重算为过期，也不能解读成今天可买。

当前实现建立可复查观察序列，尚未实现跨期价格变化计算、交易费用盈亏、冻结样本组/固定观察周期或样本外收益验证。历史价格是Steam钱包市场口径；满足规则不证明现金低估。没有强制只保留通过项，未通过/未知也可进入观察。
