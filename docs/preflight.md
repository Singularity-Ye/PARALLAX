# 保存证据的交易前检查 v1

这个切片回答“本轮选择现在还满足哪些条件、还缺什么”，不是交易许可。`mode=saved_evidence_only`，`execution_allowed=false`，没有令牌、平台请求、资金预留或订单。原项目 A 的 `routes/candidates.py` 会刷新 BUFF/Steam、检查涨价/数量/风险，并签发 90 秒一次性进程内令牌；本轮先接不可覆盖检查记录，实时复核与持久化原子授权留给后续订单阶段。

## 合同与使用

策略中心 → 交易前证据检查。选择已保存研究及账户，可减少数量、取消商品，不能增加原计划数量。每份最多100个唯一商品，数量正整数；报价期限1–300秒（UI初始90），实际取其与原计划期限的较小值。`item_key` 是计划内的规范身份键；Steam盘口同样按它匹配，不能拿显示名称混用。

```json
{"evaluation_id":"saved-evaluation-id","account_id":null,"selections":[{"item_key":"plan-item-key","quantity":1}],"max_quote_age_secs":90}
```

- `POST /api/preflights`：201 表示检查已保存，包括 fail/unknown；不表示可交易。
- `GET /api/preflights`：最近20份摘要。
- `GET /api/preflights/{id}`：原始完整快照，读取不重算。
- 引用不存在404、账户绑定/数量/语义错误400；JSON结构/未知字段422；跨站写入403，请求体上限32KiB。错误不保存记录；所有响应no-store。

账户可省略以检查演示/无账户研究的缺项。已绑定账户的研究、BUFF/仓位计划不能改到其他账户或通过省略解除绑定。研究版本来自原记录，不自动采用最新修订；更换报价/增加数量须先生成新计划与研究。

## 实际检查

1. 演示来源阻断；重新运行原策略版本，按当前时间校验原报价、FX、历史与压力盘口。只汇总所选商品，未选商品失败不污染选择。
2. 原商品报价、BUFF/Steam显式证据各自检查时效，未来时间拒绝，不以读取/重算时间刷新报价。
3. BUFF证据绑定账户、凭据代次、goods_id、计划单价、最低档首屏可见数量。可见量并不锁单。
4. 已引用价格历史绑定当前Steam凭据代次；检查两个平台本地会话元数据、Steam主体身份、300秒验证时效，以及会话/BUFF全局挑战和冷却。数据库在一个读事务中取得账户、公开SessionView和BUFF策略；不读取credential_key或凭据库。
5. 实时刷新/价格容差、真实可用余额/预留、完整持仓、平台实际费用、持久化订单/对账目前明确为unknown。因此任何“证据满足”也不会得到执行授权。

结果包含原研究、当前时间重算研究、账户/代次上下文、具体选择、按选择数量计算的CNY现金合计和逐条checks。`evidence_status`只汇总所选规则/报价/身份代次证据，`status`还包括会话、访问限制和未实现的执行条件；fail优先于unknown，全部已知满足才pass。总状态当前最多unknown。没有有效期令牌；未来不能直接消费此记录下单。

## 分层与验证

`domain/preflight`组合已有策略规则；`application/preflight`只依赖仓储ports；SQLite新增`preflight_inspections`追加表，兼容旧库、不修改原研究/计划；HTTP和统一JS/类型声明提供合同。策略中心复用主题、卡片、按钮、币种格式化，不在JS重算金额。切页/刷新保留输入，失败保留原结果，保存成功与记录刷新失败分别提示。

运行 `cargo test --locked --offline preflight`。新增9项覆盖数量/重复、时效/未来、账户/代次/身份/挑战、最低档/价格、缺证据/演示、未选商品隔离、跨站、未知字段、重启与不可覆盖；完整144通过、0失败、2默认忽略，fmt/Clippy/JS语法/debug构建通过。真实平台协议仍未验收。

浏览器用已有演示研究只选1件、数量1、期限60秒，保存现金¥5.00的fail记录；空选择失败保留输入和原结果，切页/列表刷新不清空，回看不重算。没有给用户库插入合成账户/平台数据，也没有发起平台请求或真实订单。
