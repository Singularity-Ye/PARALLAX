# 所选商品横向比较

2026-10-25。已实现保存研究的并列表；不是全市场排名或回测。

## 操作与复用

策略中心选择研究账户和已保存的持有观察策略，勾选1–20个不同商品的已保存历史，创建独立研究；也可打开已有独立研究。表格列出原结论、原币参考日价与日期、覆盖/缺失、原始/清洗CV、七日趋势、P10、未满足/未知规则及采集时间。保留全部结果与原顺序，不只展示通过项。

domain/candidate_comparison仅投影原HoldingResearchReport；不调用evaluate、不请求平台、不改写数据库。GET `/api/accounts/{account}/holding-research/{id}/comparison`复用原账户所有权检查，同源/no-store，404隔离不存在或其它账户研究。返回report_id/strategy_id/revision/research_at/rows/limitations/execution_allowed=false。原创建/详情接口与旧快照格式不变。

web/lib/candidate-comparison.js复用api.js/types、pricing-view的原币展示和规则名称；失败局限于比较区域，原研究不消失，允许重试。切换账户/报告后丢弃迟到响应。表格局部横向滚动，不给页面引入新评分算法。

## 可比性

同组要求来源、明确同币种、历史日期范围、窗口、滑点、算法和basis一致；组号仅在本份报告内有意义。不同币种不换标签或直接排序价格；不兼容组并列但明确分组。缺失/重复身份历史的行保持未知，不把缺值写成0。即使同组，采集时刻也可能不同，历史价格也不等于同时可成交现金价。

判断、时效与指标均保留原研究时点，不把旧pass描述为今天可买。低CV、较高P10或低单价没有合成“最好商品”，未启用规则仍在原研究显式显示。

## 历史行情与样本积累各负责什么

用户指出SteamDT已有历史行情，因此不应把等待自采样本当作研发门槛。优先复用供应商历史做回放；本地观察保留当时商品范围、规则版本、选中/落选、数据缺口与执行假设。行情序列与决策记录不是同一类数据。

官方资料核查：SteamDT提供K线接口 `/open/cs2/item/v1/kline`，说明“不包含成交数据”；开放平台使用API_KEY。官方权限页列K线每分钟120次，但权限、返回字段、粒度、起止覆盖仍须以实际账户和响应验证。本项目当前SteamDT适配仍是挂刀榜单参考，历史来自Steam认证pricehistory；尚未接SteamDT开放K线，未申请/读取新密钥。

来源：https://doc.steamdt.com/ 、https://doc.steamdt.com/428124801e0 、https://doc.steamdt.com/6369437m0 。核查日期2026-10-25。

后续历史回放需：只用决策时点之前的数据计算信号；信号之后的日期评估结果；明确固定商品范围、缺失/退市样本、时区、费用和成交假设；规则调参期与验证期分离。没有当时可得数据/历史商品范围时只能声明限制，不能伪造完整历史盘口。上述为设计，未实现回测、样本外胜率或收益验证。
